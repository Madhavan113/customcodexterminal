# Codex Noir: terminal-only working context

The user's latest direction is authoritative: customize the real terminal. Build no desktop application, web wrapper, canvas overlay, AppKit window, or xterm frontend. The earlier Dragon Terminal prototype is preserved at the `app-prototype` Git tag and locally under ignored `output/app-prototype/`.

## What this project is

A personal terminal setup: a macOS Terminal profile, a zsh prompt, and a patched version of the real Codex Rust TUI. Start it with `codex-noir` inside an ordinary terminal. Keep the stock `codex` command, authentication, settings, model selection, permissions, sessions, input handling, and tool execution intact.

The project is based on OpenAI Codex 0.153.4. **Edit the canonical renderer files in `src/` in this repository.** `scripts/prepare-source.py` copies them into the pinned upstream checkout for building, defaulting to `build/codex-rust-v0.153.4/`. Use `--checkout` and `--archive` to reuse a source cache elsewhere; check that it exists before relying on it. Read the upstream `AGENTS.md`, `codex-rs/tui/styles.md`, and `codex-rs/tui/src/bottom_pane/AGENTS.md` before Rust work. Avoid editing generated checkouts directly unless the current task explicitly assigns that path.

For integration-patch changes, preserve the previous patch and pass it with `--previous-patch` when reusing a checkout, or prepare a fresh checkout. Source preparation validates the overlay before migrating the integration, then applies the planned copies and removals. It removes obsolete files only when they match the previous stamp and refuses to overwrite or delete local edits. `scripts/noir_project.py` shares pinned metadata and hashing with the installer. Regression tests run with `python3 -m unittest discover -s scripts -p 'test_*.py'`.

## Agent workspace

`noir` is the terminal-only agent workspace alongside the existing `codex-noir` TUI and `claude-noir` companion. Its source launcher is `bin/noir`, entry point `scripts/noir-workspace.py`, and modules live in `scripts/noir_workspace/`. Textual presents agents and their exposed children, conversation/activity logs, live task/Git diffs, a permission/question inbox, and native message/interrupt controls. A private Unix-socket daemon owns the Codex App Server and official Claude Agent SDK connections, so closing a UI leaves tasks running. It controls sessions launched through Noir; independently running terminal sessions are not automatically attached.

`scripts/install-workspace.py` previews by default and installs with `--apply` into versioned `~/.local/share/noir/releases/` environments and `~/.local/bin/noir`. Dependencies are pinned in `scripts/requirements-workspace.txt`. State, transcripts, and task baselines stay under private `~/.local/state/noir/` project directories, not Git; test captures stay under `output/`. Preserve provider settings and native permissions. Do not simulate terminal input or claim that shared-folder Git diffs identify a particular writer. Task baselines include dirty starting files; optional worktrees start at HEAD. Drafts and cursor positions must survive background updates, agent selection, modal dialogs, and resizing.

After installing workspace dependencies in `.venv`, run `.venv/bin/python -m unittest discover -s scripts -p 'test_*.py'`, `.venv/bin/ruff check scripts`, and `.venv/bin/ruff format --check scripts`. `scripts/verify-workspace.py` additionally checks the installed Codex and Claude CLIs against isolated local streaming fixtures, including native interruption and Claude permission denial, without model API calls. Workspace-only Python edits do not require a Rust rebuild.

## Terminal renderer

Within the upstream checkout:

- `codex-rs/tui/src/bottom_pane/chat_composer/noir_scene.rs` wraps the existing composer in a separately reserved decorative region. The content is photographic halftone/ASCII and a Moire field.
- `noir_scene_tests.rs` beside it covers layout, cursor/draft safety, animation lifecycle, and snapshots.
- `noir_frame.rs` caches one decorative frame by scene, style, drive, quantized playback time, geometry and terminal appearance. Keyboard and status redraws reuse it between animation ticks; composition still skips occupied cells and preserves existing styles. Its tests compare cached output with the original painter.
- `noir_photo.rs` parses and samples bounded grayscale frames; its tests are in `noir_photo_tests.rs`. All `noir_*.rs` modules have matching editable files under this repo's `src/`.
- `noir_halftone.rs` handles Braille/ASCII painting, photographic crop geometry, a deterministic Moire field, the drifting glow that lights the Dither scene, and color adaptation. Its tests live in `noir_halftone_tests.rs`.
- `noir_dither.rs` paints the screen-fixed 8×8 Bayer ordered dither as foreground-only Braille dots; its tests are in `noir_dither_tests.rs`. `CODEX_NOIR_STYLE=dither` applies it to any scene. `CODEX_NOIR_SCENE=dither` is the full-bleed background scene: the Coast photograph spans the whole band with no caption (the user wants no labels there), lit by three drifting soft lights. It defaults to the dither treatment; other scenes default to the halftone.
- The reasoning effort sets a `Drive` in `noir_scene.rs`: Cruise, Overdrive at Max (hot palette, sweeping beam, streaks via a wider sample box in `Shot::ink`, 50 ms tick), Warp at Ultra (`noir_warp.rs` star stream from a vanishing point, 33 ms tick; the picture fades over `WARP_JUMP` seconds). Idle frames always use Cruise. `CODEX_NOIR_DRIVE` pins a level; `Palette::new` takes the drive.
- `noir_activity.rs` and its tests paint the existing activity rail in an unused composer border. Effort labels reflect actual settings.
- `chat_composer.rs` and `bottom_pane/mod.rs` contain the existing integration. Keep edits out of their input/paste state machines.
- `chatwidget/rendering.rs` composes the active transcript with the bottom pane at zero flex; its existing wrapper geometry gives input priority when the scene cannot fit. The render implementation is in this submodule, not the large `chatwidget.rs` file.
- `codex-rs/tui/assets/noir/` holds embedded luminance frames. The existing `assets/**` Bazel compile-data glob covers them.

The scene must yield space to typed input, vanish for popups or insufficient geometry, keep buffer accesses bounded, and never overwrite nonblank content. Animation advances only during visible work; its clock resets while idle or hidden. `-c tui.animations=false`, `CODEX_NOIR_SCENE=off`, and the legacy `CODEX_NOIR_DRAGON=0` must disable it. Respect terminal color capabilities and both dark and light backgrounds. The renderer precomputes colors per frame to avoid a full 256-color search for every image dot. Dither is the default scene and Coast the panel variant; `CODEX_NOIR_STYLE=halftone|ascii|dither` selects the treatment, defaulting to halftone for the photographs and dither for the Dither scene.

## Visual direction

Reference: https://madhavanprasanna.com/. Its real birds-in-flight MP4 becomes a fine textured image grid. Bring that sense of velocity into terminal glyphs: continuous motion, photographic forms, controlled grain, negative space, restrained color. Keep normal code and conversation highly legible.

Use actual photographs or sampled footage as glyph source data. No generated AI imagery, cartoon dragon, fake telemetry, arbitrary glitch spam, or ornamental rainbow effects. Flight uses frames from the user's website; Transit uses Mario Calvo's long-exposure subway photograph; Coast uses focal insight photography's rocky coast. Sources are recorded in `assets/SOURCES.md`.

The user's later references add lavender and pale acid-yellow halftones, rocky silhouettes, and warped rounded-square/dot interference. The `moire` scene is explicitly allowed to use a deterministic mathematical field to interpret the abstract reference. The native macOS Terminal wallpaper combines the Coast photograph with a very faint stationary field on dark violet. `scripts/prepare-background.py` builds it; `scripts/install-terminal.py` installs it with a native image bookmark. The wallpaper is static; the TUI scene supplies the motion. Keep the regular text and command area legible.

The `.nrf` format is grayscale source data, not prebuilt terminal escape sequences. A 16-byte little-endian header contains magic `NOIR`, version u16, width u16, height u16, FPS u16 (zero for stills), and frame count u32, followed by row-major u8 pixels for every frame. The renderer alone emits safe display glyphs. Current inputs are 160×90; Flight has 41 frames at 12 FPS, and Transit and Coast each have one frame.

Parser limits are 256×144, 256 frames, and 24 FPS. A zero-FPS still has exactly one frame. Keep parser and converter limits consistent when changing the asset pipeline.

## Claude Code companion

`bin/claude-noir` wraps the real `claude` in a private tmux server (`terminal/claude-noir.tmux.conf`): a top pane (default 8 rows, `CLAUDE_NOIR_ROWS`) runs `scripts/claude-dancer.py`, which animates Claude Code's mascot across the pane with a lavender dither trail and a shiba running on its right (red coat, cream muzzle and legs, black nose; the user's reference photo is a red shiba), and the bottom pane runs `claude` with the user's arguments. Asymmetric sprites turn with the `MIRROR` glyph table, not string reversal; the mascot keeps its original reversed "flip". The pane's bottom row is the effort rail, the Claude counterpart of the Codex band: a centered bold label (`CLAUDE · THINKING · XHIGH`, tool name, `WAITING FOR YOU`) on a line colored by drive (`cruise` cyan for high, `overdrive` magenta-amber for xhigh, `ultra` purple for max and `ultrathink` turns, rainbow for ultracode, slate for low/medium, amber while waiting), animated only while Claude works; the dancer also tints the tmux divider to match. The launcher registers `scripts/claude-pulse.py` as an async command hook through an inline `--settings` (hooks merge with the user's own; skipped if the user passes `--settings`) and gives both panes `CLAUDE_NOIR_STATE`, a JSON file under `~/.local/state/claude-noir/` removed on exit. The pulse folds hook events into phase/tool/effort/ultracode/ultrathink, taking effort from the hook's `CLAUDE_EFFORT` environment, then the event's `effort.level`, then settings; it always exits 0. `scripts/install-claude.py` installs the four files under `~/.local/`. Without tmux, inside tmux, or with `CLAUDE_NOIR_DANCER=off`, the launcher runs plain `claude`. `scripts/test_claude_noir.py` covers the frames, rail, and pulse. The Terminal wallpaper is a user-chosen Cosmos image shown in its original color (`scripts/prepare-background.py --photo`), also layered over Cursor's terminal panel through the `shalldie.background` extension. The zsh prompt colors the path cyan, branch magenta, marker yellow, and exit status red (the user rejected a rainbow prompt). `terminal/palette.json` plus `scripts/apply-palette.py` are the single source of the vivid ANSI palette for Terminal, WezTerm, Ghostty (`terminal/ghostty.conf`), and Cursor; all profiles use a blinking bar cursor, including the claude-noir tmux layout. Terminal.app's background bookmark must stay NSKeyedArchiver-wrapped or the profile import silently fails. Because Ghostty cannot animate backgrounds, `patches/ghostty-animated-background.patch` (GIF decoding in `pkg/wuffs/src/gif.zig`, frame swapping in `src/renderer/generic.zig` via `hasAnimations`) plus `scripts/build-ghostty.sh` build a patched Ghostty 1.3.1; the Zig side compiles and its renderer tests pass with Command Line Tools alone (Metal tools stubbed), but packaging the app needs full Xcode (`xcodebuild`, `metal`), which this machine lacked on 2026-09-07. Because Terminal.app cannot animate wallpapers, `terminal/wezterm.lua` (installed by `scripts/install-wezterm.py`) reproduces the profile in WezTerm with the user's Cosmos GIF playing as a background layer under a translucent wash; Terminal.app keeps the GIF's first frame.

## Collaboration

Codex coordinates assets, shell/profile changes, durable packaging, builds, QA, Git, and installation. Claude handles the bounded renderer/design task assigned in its current prompt. Do not change the other agent's files, run concurrent Cargo commands, commit, push, install, or launch additional agents unless assigned explicitly.

Codex runs upstream-required `just test -p codex-tui`, reviews relevant snapshot changes, runs `just fix -p codex-tui` for substantial Rust changes, and finishes with `just fmt`. Use `just test`, not direct `cargo test`. If reusing a local toolchain/cache environment, load it before running these commands. Interactive builds and installation default to the optimized `release` profile; `CODEX_NOIR_BUILD_PROFILE=dev-small` explicitly selects an unoptimized development build. Tests may use `--cargo-profile dev-small` and Clippy `--profile dev-small`. `CARGO_TARGET_DIR` may point to a reusable build cache. The installer respects the same profile and target directory as the build script.

Prompts, session IDs, transcripts, and local captures stay in ignored `output/` or `.agents-local/`. Put reusable codebase knowledge here. Report files changed, design decisions, and any unresolved concerns honestly.
